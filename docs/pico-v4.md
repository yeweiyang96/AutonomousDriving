# ADRV v4 时间序列

v4 复用 v3 的设备 boot、取消 epoch、session、请求 token 与有符号半区间序号排序。所有整数小端。旧 v3 40/48 字节协议仍可单独使用；新客户端只接受 v4 80 字节响应，不能降级。

## 请求

原 40 字节头保持偏移：magic `ADRV`，version=4，op，lease_ms，hold_ms，保留，token，boot，epoch，session，seq，modifier，keys[6]，保留。QUERY=0、OPEN=1、有限 SET=2、STOP=3、RENEW=4；诊断继续走独立 v3 DIAGNOSTIC=5。WINDOW=6。

WINDOW 头中的 hold、modifier、keys 必须为零，lease_ms 客户端固定 250。后面添加：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 40 | u32 | 窗口 revision，必须向前且非零 |
| 44 | u32 | 一次性动作 event_id，普通窗口为 0 |
| 48 | u16 | 分段数量 1–16 |
| 50 | u16 | 保留 0 |
| 52 | u32 | not_after_ms，设备单调时钟绝对截止时间 |
| 56+10*i | u16,u8,6*u8,u8 | duration_ms、modifier、keys[6]、保留 0 |

每段 20–200 ms，总长 ≤200 ms；物理容量 16 段，因此当前时长上限下实际最多容纳 10 个最短分段。最大帧缓冲 216 字节。解析须完整通过后一次性替换未来序列，替换过程中不插入全释放。新窗口首段可继续保持已有 W。

截止时间来自近期已匹配响应的设备 uptime，加最多 200 ms；客户端不补加 RTT，因此传输延误只缩短授权。固件拒绝已过期或超过 200 ms 的截止时间。设备时间、序号按 uint32 回绕比较。

## 响应

前 48 字节保持 v3 状态布局，但 version=4。后 32 字节：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 48 | u32 | 当前接收的 revision |
| 52 | u32 | 已提交 USB 的 revision |
| 56 | u32 | 已完成 USB 传输的 revision |
| 60 | u32 | 当前窗口首次 USB 接受时刻；未开始为 0 |
| 64 | u32 | 距绝对截止剩余 ms；无窗口为 0 |
| 68 | u32 | 已首次提交的一次性 event_id |
| 72–75 | 4*u8 | 当前分段、总段数、已提交分段、已完成分段 |
| 76 | u32 | 时间序列能力，当前为 1 |

时间戳为零也可能是回绕结果，是否开始/提交须结合 revision 和状态判断。完成确认来自真实 TinyUSB 回调，并受现有取消身份与在途报告跟踪保护。它不证明游戏处理了输入。

## 时间轴、去重与停止

首段从 USB 接受报告时开始计时。每次切换保持完整按键状态，并从实际提交时刻计算本段时长。正常 USB 调度允许小于 5 ms 的边界抖动；背压超过这个界限清空窗口，不跳过分段或压缩旧动作追赶。绝对截止时间始终不延长。

同一 seq 的完全相同请求幂等，不能重启时间轴或延长租约。不同内容重复 seq、倒序 seq/revision 被拒绝。非零 event_id 在接收时即消耗，重复新窗口不能重放它；丢失动作需要停止并重新判断，不能猜测切换结果。客户端在确认 event 已 USB 提交前不替换它，也不会跨重新规划反复触发走跑切换。

RENEW 只延长会话租约，不修改执行时间轴、not_after、event 或提交/完成进度。STOP 优先撤销 epoch，清空序列并安排全释放；窗口耗尽和 USB 延误分别记录停止原因 9、10。旧会话延迟包不能复活动作。失焦、无效数据和用户停止由客户端立即发 STOP；通信丢失仍由固件截止/租约独立释放。

生产 C 通过主机 DLL 与 Python 客户端互通测试，覆盖连续替换、W→W+A→W、事件去重、乱序、过期、续租、USB 背压、时间回绕与停止。主机测试不能替代 RP2350 两核实际 IRQ、无线和 USB 时序验收。
