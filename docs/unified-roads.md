# 统一道路与碰撞导航

正式入口 `Planner.plan()` 在统一道路图中选路，再由碰撞导航生成完整可执行路径。来源和原始审核标签只用于追踪，不参与运行时优先级。整片粗地形网格、无道路引导的全程备用搜索，以及“野外更短便替换道路”的规则不参与正式规划。

本文说明保留源拓扑的路网模型。**活动版本以 `data/roads/manifest.json` 为准**，候选目录生成完成不代表已切换。最终候选与活动包验收记录分别为 `runtime/road-topology-rebuild/candidate-final-gate.json`、`active-final-gate.json` 及其配套道路、拓扑报告。不要从文档中的候选名称或边数推断发布状态。

2026-10-30离线发布记录：`eef4b39ce057a24a`，28,853个节点、30,514条道路边及2,425条碰撞验证连接，无孤立伪节点；393项测试、候选和活动包完整门禁均通过。导航几何身份仍为 `7a4606dd9c967264`，1724块瓦片及查询DLL保持不变。回滚指针保存在 `runtime/unified-road-releases/20261029T232215Z/`。这不是游戏实走验收记录。

## 道路与连接

- 保留来源的原始节点和边：AzerothGPS 的 `n/e`、原有道路节点及其路口身份进入统一图。折线形状点、碰撞采样点和局部避障拐点不自动成为图节点，不再按8码采样制造大量道路碎片。
- 道路中途接入、声明入口或重合走廊对照确实需要拆边时，保留原始节点别名、边ID和替代关系。仅平面接近不能把两条路焊接；桥上桥下、建筑内外和不同楼层必须分别验证。
- `road` 表示来源中的道路，按该方向完整碰撞路径的实际长度计价。`connector` 是明确的道路连接边，按实际长度的两倍计价。它连接不同源路网分量、声明的门口／洞口或核对过的重合接头，不把任意可走地面自动变成道路。
- 道路分量与已声明入口的候选连接沿用AzerothGPS的200码范围；40码限制只用于 `city` 废墟道路。洞穴／室内图中 `portal=False` 的内部节点不能借此任意跨接。候选范围只负责找连接，完整碰撞路径、楼层和预算验证仍是发布条件。
- 连接的直线仅是参考和展示。完整正反向碰撞路径验证后才可发布；运行时仍验证所选连接。断路时排除失败连接并重搜其他图内道路，不把剩余整段交给开放野外寻路。
- 对已审核采集线和城市／洞穴／室内专用图的重合走廊，核对共同入口、出口、楼层及完整替代连接后，以专用道路链作为规范几何；原线来源和路口身份保留在替代道路及入口、出口连接中。普通来源的重合道路也按完整走廊对照，不能只比较两个采样点是否重合。

每条道路保存不变的原始参考走廊 `reference`，正反向验证共享这一来源约束；`points`、`reverse_points` 分别保存两个方向的完整实际路径。绕开障碍后正反向几何可以不同，不能把正向避障结果倒过来当作反向查询的新道路中心线，否则原本有效的整条道路会被错误判为不通。局部重试仍受同一原始道路的3、9、24码走廊约束，24码是最大范围。

## 来源、表面与楼层

两大陆输入共 **29,625 条来源记录**：原有道路6902条，AzerothGPS Roads 2409条、Cities 3396条、Capitals 4948条、Caves 8654条、Indoors 3308条，以及带逐点高度的 FloorTracks 8条。其中补回了旧过滤遗漏的417条 Roads `source=2` 步行连接、684条嵌套城市道路及8条 FloorTracks。电梯、交通工具、游泳、跳跃和跳落不会因导入而启用。

原文件摘要、原始节点和边ID、声明入口、楼层信息及旧版本声明保留作追踪；AzerothGPS 的旧数据不冒充当前客户端重新提取的数据。参考插件与服务端资源只读，候选写入 `runtime/`，正式路网写入 `data/roads/`。本次道路重构不改变导航网格生成规则，也不重新生成现有1724块导航瓦片。

专用道路绑定实际碰撞表面、原始楼层和出入口。只有连接双方都明确提供了 `source_height`，才应用5码的来源层差限制；不能拿原生地形高差冒充楼层差，否则同一条正常坡路会被误拒。

一个二维洞穴绘图可能同时投影到地下道路和上方地形。对 cave／indoor 的每个原始 source graph 道路组件，要求至少有明确来源楼层或声明入口支持；缺少支持的组件记为 `unbound_surface_component`，保留诊断，不作为道路发布。即使上方地面静态可走，也不能把它归成洞穴道路，让“零码接路”抢先锁住实际洞口。

路网按瓦片保存正反向几何及验证分片，记录碰撞多边形锚点、方向长度、验证结果、源文件摘要，以及匹配的导航身份和 DLL 摘要。缺失表面、楼层不明或搜索超限均进入问题报告；“来源已处理”不等于“全部来源均通过验证”。

角色楼层仍依据实际位置序列、已确认楼层和局部碰撞连通性跟踪。道路和区域信息只辅助筛选；路线可以到达某层不能证明角色就在该层。起点楼层不明时暂停，不能猜层启动。

## 接路与预算

两端通过空间索引逐批扩展，分别最多选择8个通过验证的入口；支持从道路中途接入，候选进入同一次图搜索。起终点接路不设绝对距离上限，按实际碰撞路径长度的两倍计价。找到最近的有效接入后，替代入口最多增加24码局部离路距离，防止把跨野外捷径伪装成接路。终点接路按驶向终点的实际方向验证并复用完整结果。

所有入口查询、失败重试和图搜索共用原有500000次展开账本，取消机制保持不变。原生节点池、384 MiB导航瓦片限制及180/250 ms控制保护不扩大。道路上的查询使用原生允许多边形集合，与原有步行、禁水和禁行连接过滤取交集，并检查完整输出；长度约束椭圆不能替代道路走廊边界。

## 地图显示与性能

细实线显示连续道路，灰色虚线显示道路间连接参考，蓝色粗线显示完整碰撞导航执行路径。虚线不是可直接执行的直线，也不是地形估算网格。旧候选开关只为设置兼容保留，旧日志中的 reviewed／candidate／terrain 标签仍可回放，不恢复旧规划策略。

显示层独立于执行图：活动指针直接引用轻量 `display.json`，不为绘制地图加载执行路网、验证分片或碰撞 DLL。JSON解析、连续线合并、空间索引和缩放简化均在独立进程完成，界面只接收可见折线。平移复用缓存并整体移动图层，缩放复用对象；新增和清退对象按约4 ms批次绘制。没有独立显示文件的旧包可以显示原始 bundle 道路，该兼容显示不授权执行。

最终活动包的943×557离线道路层测试中，大陆、丹莫罗和铁炉堡平移重绘中位为 **1.191 / 0.924 / 0.547 ms**，缩放中位为 **1.243 / 1.183 / 0.640 ms**；测试直接读取活动指针，未用原始 bundle 回退。旧大陆道路层平移中位为3263.7 ms。并行门禁期间单次平移最高47.313 ms，中位数不是硬实时上限。活动报告为 `runtime/road-topology-rebuild/active-display-benchmark.json`，五组真实几何对照图在 `runtime/road-display-performance/candidate-v5-comparison/`。这些数值不包含底图绘制，也不能代替实时控制或游戏实走验收。

## 构建、门禁与发布

1. 明确使用的导航包与原生 DLL。若 DLL 改变，用 `tools/stage_road_navigation.py --native-library <明确DLL> --output <新导航候选>` 组合既有瓦片；不重新生成几何，也不修改运行中的服务端数据。
2. `tools/build_unified_roads.py --manifest <导航清单> --output <新道路候选>` 调用源拓扑构建器，验证完整原边、融合规范几何、生成显式连接、方向验证记录和独立显示文件。
3. 对该候选运行完整门禁：

   ```powershell
   ./.venv/Scripts/python.exe tools/check_navigation_regressions.py `
     --manifest '<导航清单>' --roads-manifest '<道路候选>/manifest.json' `
     --report runtime/road-topology-rebuild/candidate-final-gate.json
   ```

   总门禁检查1724块导航瓦片、原生能力、桥梁／长路线／Westfall／705码案例、每条发布连接的完整双向碰撞结果，并调用 `tools/check_road_topology.py`。
4. 拓扑门禁检查原始节点身份和别名、节点度数、孤立节点、方向代价、原始路口及替代链；还对铁炉堡三个原始路口执行六条正反向完整路线回归，核对原始坐标、楼层、连续性和绕行质量。`agps:Caves:0:0:1676` 是必须保留的完整来源回归，删除它不能让“剩余边都通过”变成合格。`--graph-only` 仅诊断，不作为发布凭据。
5. 候选总报告及配套完整道路报告均通过后，用 `tools/publish_unified_roads.py --candidate <候选> --navigation-manifest <导航清单> --road-report <完整道路子报告> --native-report <候选总报告>` 发布同一份候选。它检查清单摘要、完整几何及拓扑门禁，保留旧指针和 DLL，再切换活动包；不能通过删除失败的回归来源、路口或替代链绕过门禁。
6. 发布后运行活动包门禁，报告写入 `runtime/road-topology-rebuild/active-final-gate.json`。只有候选与活动检查均通过才算完成离线发布；`--skip-full-load` 不是发布门禁。

来源和问题明细在版本目录的 `audit.json`，普通预览诊断为 `runtime/route-quality/last-plan.json`，回滚清单位于 `runtime/unified-road-releases/`。保留旧数据和历史修复证据。私有 `_plan_coarse()`、底层 `NavMeshPack.plan()` 和旧碎片构建诊断仍供历史几何比较，不能作为控制器的正式规划入口。

## 验收边界

静态碰撞验证证明所选几何可步行，不证明道路上没有怪物、动态门已打开或角色已实际完成路线。道路长度与绕行质量以本次路网门禁报告为准，不要求返回历史717码野外捷径。游戏内沿路、桥梁、洞穴和多层建筑实走必须使用当前客户端、可靠遥测和已确认楼层，另行记录；离线通过不能代替实走。
