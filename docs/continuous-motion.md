# 连续地面移动 v4

默认控制使用插件 0.4.0、AD 遥测 v4、ADRV v4 固件 0.6.0-motion，以及带 `ad_motion_corridor_v1` / `ad_motion_validate_v1` 的 native DLL。旧遥测可观察，旧固件可诊断；新模式不自动降级。跳跃、游泳、飞行、船和电梯不属于本轮移动方式。不会自动上坐骑。

## 按键与速度

默认 W 前进、A/D 转向、Q/E 平移、数字键盘除号切换走跑，六个键都可配置且不能重复。移动决策是完整按键集合，例如 W、W+A、W+Q、Q+D。运动控制不生成仅 A/D 的原地转向；只有用户主动启动的校准会短暂原地转动。

插件每个有效帧读取 `GetUnitSpeed('player')`，目标 30 Hz。currentSpeed 为实际速度；runSpeed 为静止起步需要的地面能力。当前速度降低立即参与时长和转弯半径计算，零速度和能力缺失分开处理，没有固定 7 码/秒补值。骑乘只提供状态，不选择固定速度档。详见 [遥测字段](telemetry-protocol.md)。

校准先左右各转两次，再分别测试 Q、E、W+Q、W+E 两轮。平移每次为 120 ms，执行前由独立进程验证当前位置周围完整净空圆盘。实测方向重复不一致、意外转头、楼层未知或空间不足均拒绝保存。组合按键使用归一化实测速度，不按两个键相加速度。移动时仅在确认的同一按键状态下缓慢修正转速，并检查连续位置变化与速度是否一致。

## 路线、轨迹、执行窗口

现有道路和楼层规划保持为源路线。在其后增加 `MotionTrajectory`、`MotionWindow`、`TimedKeyframe`：

- 仅在有限的原路线进度区间内合并短折线，不用全局最近点跳到回环后半段。每次合并必须通过完整地面检查。
- 正常转角生成相切圆弧，入口、出口在对应源线段上，半径按当前水平速度和左右实测转速决定，保留转向纠偏余量。坡道用表面三维长度折算水平速度。
- 轨迹保存前方至少约两秒的参考几何，并保留更长的局部源路线用于弯道检查。每次只预测、发送最多 200 ms 的按键；新遥测到达即可替换未来动作，没有等待整段走完的固定延迟。
- 朝向和位移方向分别预测，比较前进、纯平移、斜向前进及其转向组合。参考轨迹使用局部单调进度和纠偏死区。
- 静止遥测不能说明当前走跑模式。需要降速时先以地面能力上界认证一小段连续移动，用新遥测确认实际速度；已经在走路时不切换。实际高速且前方仍安全时才发送一次走跑切换，等待实时速度下降确认。任务内不重复切换，也不以反复松 W 降速。本轮切换后维持走路，不自动切回跑步。
- 起步朝向与路线不符时，比较实测前进、平移和斜向运动方向，生成与首段相切的圆弧—直线—圆弧接入路径；整条接入路径通过原走廊和净空检查后才允许移动。接入期间保持选定的移动方式，避免相邻帧在相反平移方向之间反复切换。
- 曲率、朝向或预测净空无法认证时暂停并记录具体原因。这些失败不等于道路拓扑不通，不能据此封锁角色所在的整个起点多边形。实际受阻或偏离仍可触发沿道路重新规划，不会使用逐点停走、原地转向或未经验证的直线兜底。
- 进度以已验证轨迹与原路线的有序对应关系推进：被合并的短段保留通过位置，圆弧替代的折线角点以出弯位置确认通过。刷新局部轨迹不能因没有踩到原角点而返回旧路段，也不能跳到回环后半段。

延长预览失败不必立即放弃正在执行的安全曲线。速度仍可执行、旧曲线剩余长度覆盖 200 ms 窗口、输入延迟与停止余量时，继续跟随原曲线，并随新观测重试续接；每次预测仍重新做完整碰撞验证。余量不足或加速导致原曲率不可执行时暂停，不能沿过期曲线继续前冲。

地图保留原路线，绿色叠加当前执行参考曲线。重新选路清除旧曲线。曲线显示不表示动作已被游戏执行。

接近终点时按输入延迟预测释放位置，先停止，再由新遥测确认速度已归零且距原始终点 ≤0.6 码。预测到达不直接标记成功；实际停止位置超差则暂停，避免自动小步来回追点。校准若观察到输入延迟超过 250 ms，会拒绝保存，不截断成较小值。

### 校准完成条件

开始按钮和 F8 在等待游戏焦点前检查完整校准；仅有旧转速记录不能启动连续导航。重新点击校准会清除旧模型，4 次转向和 8 次平移/斜向测试全部通过后才一次保存两组结果。失败或取消不会留下可用于起步的半成品模型。报错使用用户实际配置的按键名称。

点击“开始”或“转向与平移校准”后，客户端会按已配置的精确标题找到唯一游戏窗口，恢复最小化状态并自动切回游戏。切换只随本次按钮操作执行一次；失败不会开始新的输入会话，已有待执行意图也会撤销。期间收到的 F12 或配置变更优先于旧按钮操作。运行时仍以实际前台窗口身份与新遥测授权输入，切出游戏后不自动抢回焦点。

窗口激活请求与实际前台确认分开处理：即使激活 API 当次返回失败，后续实际前台和 PID/标题匹配仍可确认成功。客户端在启动前最多等待 1 秒，用 Tk 回调每 20 ms 只读复查，确认后立即继续；不阻塞控制线程，不重复激活，不给正常移动增加固定等待。F8/F12、配置变化、新的按钮操作或关闭客户端会取消旧请求；超时后到来的切换不会启动已取消的任务。

窗口操作使用 Windows 的 [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow) 和 [ShowWindowAsync](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindowasync)，不模拟按键或鼠标，也不修改系统前台窗口限制。

v4 校准先用不同遥测帧确认角色静止。每个短动作的固件零报告之后，还需要至少三个不同的新遥测帧形成两个稳定区间：朝向变化小于 0.2°、位置变化小于 0.04 码、插件实时速度不超过 0.05 码/秒，并且确实观察过动作生效。重复读取同一帧不能推进判断；持续转动、移动或没有响应仍由原有观察超时终止。该过程只用于校准取样，不给正常连续导航增加等待。

日志 `calibration_sample` 记录起点、稳定区间起止帧、首次生效和零报告观察时间，便于区分 USB 结束与游戏内动作结束。转向重复测量 25% 和平移方向差异门禁仍保留。

## 碰撞与时效

运动工作进程拥有独立 Detour 实例。控制线程只读取最新结果，不等待 native 搜索。单个进程最多一个在途观测，避免旧帧排队。结果绑定路线版本、遥测会话/帧、运动模型版本、导航身份和 DLL SHA；超过 80 ms、速度明显改变、位置不符、换地图或导航包改变的结果不能授权移动。

读取 manifest、Windows 子进程启动和终止回收均由后台生命周期线程处理；控制线程启动、取消和轮询不等待这些操作。取消中的迟到启动结果不能重新授权输入。只有子进程已返回匹配的导航身份时才接收运动请求。

运动走廊保留 Detour 多边形身份。源路径接缝存在浮点边界误差时，只允许在提取拓扑时识别 0.0025 码以内的原接缝；这不授权移动或移动终点。连接搜索最多 256 次扩展。实际轨迹仍要求严格地面定位、完整射线、相同楼层、跨瓦片连接和额外净空。

当前道路模型没有独立的人工必经锚点标记；多边形走廊集合与有序源进度不能替代这类锚点的逐个经过证明。短折线合并仅在局部 12 码内、沿候选方向单调且整段扫掠通过时允许；长共线门户可以合并，回环倒退段不能跨过。

线段的线性高度可能穿过同一地面的小隆起。原始扫掠不通过时，工作进程可按不超过 0.10 码间距查询同一走廊内唯一的邻近地面（相对参考高度不超过 0.50 码），然后以原净空重新验证整条扫掠。源路线的入口、出口保持原坐标；短时按键预测保留首个观测点，后续预测点允许贴合同一地面。缺失、歧义、跨层或最终扫掠失败均不能授权移动。每次请求的查询数量有上限，缓存绑定走廊和导航实例。

圆弧按最大 0.01 码弓高误差细分。每条弦最多按 0.20 码分段，并用边界距离的 Lipschitz 下界验证整个子段的扫掠范围。额外净空包含位置取整、跟踪误差、观测/发令时差、输入延迟不确定性、USB 调度及短窗口模型误差；不能用端点或稀疏采样放行。角色半径、地面过滤、水域规则和生产瓦片均未放宽。

最短导航折线可能贴着已膨胀边界，本身不等于可执行曲线。桥梁几何回归分别记录源拓扑可解析、哪些点具有额外净空，不能把拓扑成功误报为整条桥梁已经实机走通。

## 保护和固件

保留 180 ms 状态确认、180 ms 新窗口 USB 提交确认、250 ms 遥测、250 ms 租约保护。窗口最长 200 ms；续租不延长窗口。窗口耗尽、失焦、失去有效数据、设备异常或用户停止会清空时间序列并释放按键。状态接收、USB 提交和 USB 完成分别记录，均不等同于游戏位移。

计算出走跑切换不代表切换已经提交。若首个计算结果因过期被丢弃，新帧仍使用同一个动作 ID 提议切换；只有收到固件 `applied_event` 才开始等待游戏速度变化。确认后不会重放切换，也不会用过期结果授权输入。

ADRV v4 的精确线格式、乱序和 USB 背压行为见 [协议](pico-v4.md)。网络核接收和回复，USB 核执行单调时间轴，保持原有分工。

## 回放诊断

日志记录每个窗口的源帧、完整分段按键、模型/路线版本、计算耗时、授权年龄、固件窗口号和导航身份；`pico_lease` 记录接收、USB 提交与完成进度。使用下面的只读命令汇总时间线：

`motion_decision` 另行记录未发令的结果、拒绝原因代码、源帧年龄和是否仍可用；`replan` 记录实际封锁的连接。可区分“未形成可执行窗口”“结果已过期”和“已发令但没有位移”，不能仅从最终接路错误推断固件没有响应。

```powershell
.\.venv\Scripts\python.exe tools/replay_motion.py runtime/logs/<日志>.jsonl --output runtime/motion-replay.json
```

汇总标出全释放、仅转向、重复一次性动作、过期授权和未确认 USB 窗口。它不会连接设备，也不会把固件确认当作角色已经运动。

## 刷写后的实机验收

本次只交付 UF2，没有刷写、发送游戏输入或完成实机验收。后续验收需人工刷写，再安装新插件、`/reload` 并重启客户端：

1. 只读诊断应显示固件 0.6.0、ADRV 3–4 和时间序列能力。停用旧遥测重叠面板。
2. 先观察站立、行走、加速、减速和地面坐骑：当前速度随状态变化，静止为零，地面能力单独有效。任一 API 缺失应拒绝起步。
3. 在空旷地面执行新的转向与平移校准。依次确认“转向 1–4/4”“平移与斜向前进 1–8/8”和“校准已保存”；失败结合 `calibration_sample`、遥测与固件时间线排查取样、绑定、鼠标右键和 API，不修改超时。固件协议兼容提示不代表角色校准已经通过。
4. 从 10–20 码直线开始，再验收左右弯、S 弯、密集短折线和回环。正常转弯应连续按住移动键，出弯横向误差目标 ≤0.3 码，最终位置 ≤0.6 码。
5. 验收步行多档速度、加减速、已骑乘地面坐骑、起步和停止，再验收走跑切换与侧移。狭窄、桥上下层、墙角、水边、坡道和跨瓦片场景必须始终处于已认证范围；无法认证应暂停。
6. 单独测试 F8/F12、切出窗口、聊天框、遥测冻结、USB/Wi-Fi 中断；确认清空窗口和释放。恢复后必须手动继续。实际停止延迟以日志和画面测量为准。

实机验收前，0.3/0.6 码是控制目标及离线仿真检查值，不能宣称为真实游戏的已验证精度。
