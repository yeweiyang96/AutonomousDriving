# 旧 Pico 接口与首版控制背景

> 2026-10-29：实测发现旧脉冲方案存在约 81 ms 的动作间隙。当前客户端行走已改用 [ADR v3 连续控制](pico-v3.md)，需要相邻 `hid_usb` 项目的 `0.5.0-lease` 固件。本文保留旧版本协议和最初实现的依据；下文的短按门控及排队释放描述仅适用于原固件。新固件命令 10 也已改为抢占释放。

原参考固件固定为 [yeweiyang96/hid_usb / b2d73c15](https://github.com/yeweiyang96/hid_usb/tree/b2d73c15ce5f9389490409fdbf77093c68aae106)。默认目的地址为 `192.168.11.7:8888`。

所有整数为小端。只用三种命令：

| 用途 | 布局 | 规则 |
| --- | --- | --- |
| 健康查询 | `<BI`：0、随机 token | 响应必须回传相同 token；过期、错误长度的数据包不能当作当前状态 |
| 定时按键 | `<BBH`：1、HID usage、毫秒 | 本项目限制 20–200 ms；W=26、A=4、D=7，可配置 |
| 全部释放 | `<B`：10 | 现有固件把它放入队列，不能立即抢占正在执行的动作 |

查询响应 24 字节，布局 `<4sBBBBIIII`：`PICO`、协议版本、flags、等待队列长度、队列容量、token、启动毫秒、accepted、rejected。当前固件动作协议版本为 2，适配器也能解码 1。flags 的 bit0、1、2、3、4 分别表示 USB mounted、键盘 ready、鼠标 ready、busy、Wi-Fi up。端点短暂 busy 不独立证明故障。

## 单动作门控

1. 在健康状态可用、设备空闲、队列为空、遥测有效且新鲜时记录基线。
2. 只发送一次定时按键，不使用无限按下命令，不重试输入数据报。
3. 等待设备回到空闲，以及发令时长 + 5 ms 之后采集的新的遥测帧。会话变化、序号倒退、设备重启、rejected 增加、accepted 增加超过 1 都转为故障。accepted 未增加时等待有界超时，不重发。
4. Controller 根据实际朝向和位移决定下一个动作。设备接收计数不代表动作完成，空闲加新帧也不是固件 ACK。

每个动作观察超时为保持时长 + 1 秒；遥测的新鲜性门限另为 250 ms。计数、启动时间和序号均按 uint32 正常回绕处理。执行期必须独占 Pico，不能同时运行其他输入客户端。即便如此，无序号 UDP 仍不能提供恰好一次执行保障，特别是迟到的重复报文；本项目不作这项承诺。

## 控制器

每条直线先对齐至 3°，误差超过 5°重新对齐。横向偏离超过 3 码时朝当前边的局部接入点纠偏；超过 15 码请求重规划。中间拐点以 0.6 码判定通过，最终终点以 2 码判定到达，不跨过尚未通过的中间拐点直接追逐终点。累计前进按键两秒但位移小于 0.5 码时阻断当前边并重规划，任务内最多两次重规划。

左右转向速度必须先校准；校准缺失不能行走。持续转向却不能改善朝向时停止，防止错误按键导致循环。角色实际位移用于更新行走速度；停止、加载、战斗等状态不会触发自动继续。

## 验证范围

`tests/test_pico.py` 使用模拟 socket 和合成状态测试编码、超时、迟到查询、计数歧义和回绕，没有向真实 Pico 发送按键。`tests/test_controller.py` 使用运动模拟验证直行、连续拐角、180°回头、速度变化、卡住和异常停止。真实 USB 输入、网络延迟、游戏碰撞与按键设置仍需分别实机验证。
