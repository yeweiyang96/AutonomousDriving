# 精细地形与碰撞导航

正式寻路现采用统一道路图，经过当前碰撞包验证后沿路行走。候选道路与已审核道路统一为道路，整片粗地形网格退出正式规划；缺少匹配道路包或碰撞包时不退回旧网格。当前数据、道路融合、接路规则及发布流程以 [统一道路说明](unified-roads.md) 为准。下文早期来源和道路引导方式保留作历史记录。

本项目复用本机 Forever 服务端的提取器、Recast 建网逻辑和 Detour 查询库，从当前游戏客户端重新生成独立步行导航包。高清图片用于显示；可行走性由三维地形、静态建筑/模型碰撞决定。

## 生成和查询

流程：游戏 CASC → ADT 地形与 WMO/M2 静态碰撞 → Recast 多边形导航网格 → Windows Detour 查询 → 带高度的完整路线 → 原有客户端控制器。

| 参数 | 当前值 |
| --- | --- |
| 水平生成单元 | 0.2666666 码 |
| 角色半径 | 0.5333332 码 |
| 角色高度 | 1.5999996 码 |
| 可步行台阶 | 0.5333332 码 |
| 最大坡度 | 50° |
| 水域、陡坡标记、跨隙/跳跃连接 | 查询时排除 |

这些参数描述网格生成，不能保证所有碰撞表面都达到同等精度。旧约 16.7 码的二维网格仍供道路偏好与缺少精细包时的兼容模式使用，不再代替精细碰撞判定。

现有服务端导航允许较高台阶，并可能加入跨隙连接，不适合直接交给不跳跃的客户端。因此本项目重新生成低台阶网格，查询时过滤全部 off-mesh 连接，包括生成器自动建立的连接。

世界坐标 `(北, 西, 高)` 转换为 Detour `(西, 高, 北)`。读取器匹配 Forever mmap 16、Detour 7、64 位多边形引用。按走廊加载瓦片，单次规划限制 384 MiB 数据；Detour 单次搜索节点池为 65,535，默认累计展开预算 500,000。完整性和预算检查失败时不返回部分路线。较长或不连通的路线可能触及预算，不能将这种错误解读为地图中必定无路。

旧道路只用作途经点偏好。每个参考点最多花费 4,096 次局部展开；不可达点或不合适的楼层可跳过，最终返回的每一段仍来自完整碰撞路径。若参考路线不能完成，再搜索精细几何中的替代路径。精细模式不承诺旧网格的“未经审核距离全局最小”性质。

道路偏好还受整体路线质量检查：当粗道路与已验证的引导路线均超过 A/B 直线距离的 2.5 倍、且均多出 500 码时，额外搜索一次不带道路引导的完整步行候选。候选沿用已解析的原始起终点和楼层、禁行连接、水域及跨隙过滤，并使用 `ad_path_bounded_v3`；只有实际长度至少缩短 20% 才替换道路路线。范围参数只是保守的几何搜索域，返回后仍检查实际长度，不保证全图最短。

两条候选及失败搜索共用原有 500,000 次展开预算，逐次查询的数据上限仍为 384 MiB。短候选因搜索范围、节点池或预算限制未验证时，可以保留已完成的道路路线，并在 `route_selection` 记录原因；不会据此宣称不存在更短路线。取消、损坏数据和楼层错误继续报错。`runtime/route-quality/last-plan.json` 同时记录选择、两条候选的长度与累计消耗；离线测试关闭普通快照写入，避免覆盖真实预览证据。

2026-10-30 的道路环线案例（大陆 0，`(-9937.311572232578, 1001.1050237878376)` → `(-10641.868693563683, 1017.8745550378376)`）在活动包 `7a4606dd9c967264` 中由约 7512.44 码缩短为 717.11 码，反向约 710.18 码。Westfall 旧检查只确认路线贴合道路；整体比较后，同一端点可用约 2311.56 码的完整步行候选替换约 6674.80 码的道路绕行。这些是静态网格结果，仍需游戏内行走验收。永久回归入口为 `tools/check_navigation_regressions.py`。

用户 A/B 必须落在实际可步行多边形内，保持原始水平坐标。实时起点自动跟踪所在表面；多层终点自动选择已验证步行路径中较近的地面，手动预览起点仍可显式指定。中间参考点可以尝试可连接的表面，不能据此移动用户终点。路径保留多边形交界和高度，不使用未经碰撞检查的直线平滑。

## 使用和更新

现有包可直接用于离线地图预览。选择终点后预览；执行起点使用实时轨迹识别的地面。蓝色表示静态碰撞导航。重新运行客户端后生效，已打开的旧进程不会自动加载新代码。

执行精细路线使用插件 0.3.0 的区域遥测（v3）。插件不获取高度；客户端自动跟踪地面。更新插件、游戏内重新加载并重启桌面程序，Pico 无需刷写。见 [自动楼层识别](automatic-floors.md)。

```powershell
./tools/build_navmesh.ps1
./.venv/Scripts/python.exe tools/export_navigation.py
./.venv/Scripts/python.exe tools/check_navigation.py
./.venv/Scripts/python.exe -m unittest tests.test_navmesh -v
```

需要 Windows x64、CMake、Visual Studio C++ Build Tools、WSL Ubuntu 及已匹配的 Forever 提取工具。构建脚本只读取游戏与服务端；临时输出位于 `runtime/`，新导航目录完整校验后才替换活动清单。`tools/extract_data.py` 不覆盖导航包。提取器升级后先核对格式与参数，不把文件复制成功当作兼容验证。

## 验证与边界

全包检查逐块执行 SHA256 校验及原生 Detour 加载。真实当前版本路线验证了两大陆跨瓦片导航及多层高度，构造几何测试覆盖墙洞、水面、不可达楼层、跨隙连接过滤、取消、预算和失败连接排除；具体结果见 `validation.md`。

当前数据仅表示静态几何。动态门、怪物、其他角色、移动运输、服务器临时障碍和角色体型差异需要额外观测。大陆内洞穴/建筑只有在实际网格覆盖且连通时才可用，副本未打包。碰撞提取与网格本身也可能存在缺口；不能通过放宽碰撞或悄悄退回粗网格来伪装成功。

真实游戏执行尚未验收。需要验证地面推定、楼梯、门洞、狭窄路段与路线偏离后的停止行为，并保存日志。静态路线生成成功不等于真实行走成功。

## 高度接口兼容修正（2026-10-30）

插件 0.2.1 不再采用 UnitPosition 第三个返回值，输出 XY 遥测。之前要求更新插件即可取得真实高度的说明不成立。客户端后台以原始 XY 查询唯一可步行表面，保留 raw_z、height_source 和原采集时间；多层不自动猜楼层，不把推定地面高度当作真实测量。既有插件传回高度（包括 0）会被拒绝，需更新插件。停止和采集新鲜度检查保持生效。

后续实现：0.3.0 增加区域上下文与连续轨迹自动跟踪，取代上述仅支持单层地面的限制。桥上/桥下暂不作为本次验收目标。
