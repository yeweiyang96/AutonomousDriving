# 精细地形与碰撞导航

本项目复用本机 Forever 服务端的提取器、Recast 建网逻辑和 Detour 查询库，从当前游戏客户端重新生成独立步行导航包。高清图片用于显示；可行走性由三维地形、静态建筑/模型碰撞决定。

## 生成和查询

流程：游戏 CASC → ADT 地形与 WMO/M2 静态碰撞 → Recast 多边形导航网格 → Windows Detour 查询 → 带高度的完整路线 → 原有客户端控制器。

| 参数 | 当前值 |
| --- | --- |
| 水平生成单元 | 0.2666666 码 |
| 角色半径 | 0.5333332 码 |
| 角色高度 | 1.5999996 码 |
| 可步行台阶 | 0.5333332 码 |
| 最大坡度 | 50° |
| 水域、陡坡标记、跨隙/跳跃连接 | 查询时排除 |

这些参数描述网格生成，不能保证所有碰撞表面都达到同等精度。旧约 16.7 码的二维网格仍供道路偏好与缺少精细包时的兼容模式使用，不再代替精细碰撞判定。

现有服务端导航允许较高台阶，并可能加入跨隙连接，不适合直接交给不跳跃的客户端。因此本项目重新生成低台阶网格，查询时过滤全部 off-mesh 连接，包括生成器自动建立的连接。

世界坐标 `(北, 西, 高)` 转换为 Detour `(西, 高, 北)`。读取器匹配 Forever mmap 16、Detour 7、64 位多边形引用。按走廊加载瓦片，单次规划限制 384 MiB 数据；Detour 单次搜索节点池为 65,535，默认累计展开预算 500,000。完整性和预算检查失败时不返回部分路线。较长或不连通的路线可能触及预算，不能将这种错误解读为地图中必定无路。

旧道路只用作途经点偏好。每个参考点最多花费 4,096 次局部展开；不可达点或不合适的楼层可跳过，最终返回的每一段仍来自完整碰撞路径。若参考路线不能完成，再搜索精细几何中的替代路径。精细模式不承诺旧网格的“未经审核距离全局最小”性质。

用户 A/B 必须落在实际可步行多边形内，保持原始水平坐标。多层地面必须指定高度，近似等距的高度也会被拒绝。中间参考点可以尝试可连接的表面，不能据此移动用户终点。路径保留多边形交界和高度，不使用未经碰撞检查的直线平滑。

## 使用和更新

现有包可直接用于离线地图预览。选择 A/B；出现多个高度时在侧栏选择，再点击“预览路线”。蓝色表示静态碰撞导航。重新运行客户端后生效，已打开的旧进程不会自动加载新代码。

执行精细路线需要本项目 `addons/AutonomousDriving` 0.2.0。将该插件更新到实际游戏插件目录并重新加载；本次只更新项目里的插件源文件。新色块 v2 增加高度，面板尺寸保持 128×64，兼容旧 v1 解码。无法取得 `UnitPosition` 高度时保留未知，不用零代替。无须因为高度协议变更刷写 Pico 固件。

```powershell
./tools/build_navmesh.ps1
./.venv/Scripts/python.exe tools/export_navigation.py
./.venv/Scripts/python.exe tools/check_navigation.py
./.venv/Scripts/python.exe -m unittest tests.test_navmesh -v
```

需要 Windows x64、CMake、Visual Studio C++ Build Tools、WSL Ubuntu 及已匹配的 Forever 提取工具。构建脚本只读取游戏与服务端；临时输出位于 `runtime/`，新导航目录完整校验后才替换活动清单。`tools/extract_data.py` 不覆盖导航包。提取器升级后先核对格式与参数，不把文件复制成功当作兼容验证。

## 验证与边界

全包检查逐块执行 SHA256 校验及原生 Detour 加载。真实当前版本路线验证了两大陆跨瓦片导航及多层高度，构造几何测试覆盖墙洞、水面、不可达楼层、跨隙连接过滤、取消、预算和失败连接排除；具体结果见 `validation.md`。

当前数据仅表示静态几何。动态门、怪物、其他角色、移动运输、服务器临时障碍和角色体型差异需要额外观测。大陆内洞穴/建筑只有在实际网格覆盖且连通时才可用，副本未打包。碰撞提取与网格本身也可能存在缺口；不能通过放宽碰撞或悄悄退回粗网格来伪装成功。

真实游戏执行尚未验收。需要验证插件高度、桥上/桥下、楼梯、门洞、狭窄路段与路线偏离后的停止行为，并保存日志。静态路线生成成功不等于真实行走成功。
