# 道路搜索范围修正：route-search-bounds-v1

日期：2026-10-30（日本时间）。适用于本次 AutonomousDriving 项目中已经安装 `surface_diagnostics_v1` 的版本。

## 这次修改解决什么

把现有的道路长度接受标准提前用于原生寻路，减少在不可能满足道路要求的远处区域继续搜索。原来的长度、道路偏离、折返、实际碰撞网格、完整起终点和禁行边检查继续执行。

这项修改作用于所有道路引导查询，没有桥坐标、模型名或瓦片编号特例。包内的西部荒野坐标仅用于安装前回归验证，不是运行时例外。

**它不会补出缺失的步行连接，也不启用游泳。** 本次约 31.52 码高度的地面在前方转为 water 标签，上方约 40 码的片区是孤立组件；不能直接把上层认成可达桥面，也不能把 water 标签改成可走地面。

```text

```

在 PowerShell 运行：

```powershell
& 'D:\wangzekun\Documents\AutonomousDriving\.venv\Scripts\python.exe' 'D:\wangzekun\Documents\AutonomousDriving\tools\route_search_bounds_v1\install_route_search_bounds.py'
```

安装器会在隔离目录编译，运行旧接口验证、新接口验证和本次实际路线回归，保存精确备份，然后切换源码与清单指向的 DLL。它不下载编译器、不停止现有进程。编译及验证期间会持续打印阶段和等待状态。

成功标记为 `ROUTE_SEARCH_BOUNDS_INSTALLED`。成功后重新启动导航程序。若验证失败，保存终端结尾和 `REPORT =` 指向的报告；不要删除校验步骤强行安装。

上传的证据覆盖原来已加载的 46 个瓦片。新搜索能完成第一层范围检查后，仍按原程序规则尝试半径 2、4 的加载范围；这会需要额外瓦片。它们不在本次上传包里，但可以从你电脑当前清单中核验。

因此，这里没有声称已用上传数据完成全部扩大范围的路线验证。安装器会在你的完整本地数据上继续验证：只有返回经完整检查的路线，或准确的 `road_connection_unverified`，且没有新的节点池耗尽、缺失数据或校验错误，才安装候选。无法通过时保留原活动版本和验证报告。

## 代码改动

### 1. 新增原生接口，保留旧接口

`native/navmesh/bridge.cpp` 末尾增加：

```cpp
#include "path_search_bounds_v3.inc"
```

新接口为：

```cpp
int ad_path_bounded_v3(
    void* handle, const float* start, const float* goal,
    int budget, float max_length_xy, Cancel cancel,
    float* output, uint64_t* refs, int capacity,
    int* count, int* expanded);
```

它沿用严格端点解析、当前步行过滤器、区域成本、禁行边、普通多边形限制，以及完整路径和高度校验。原有 `ad_path`、诊断接口和 Detour 源码不修改。

设原来能接受的道路长度上限为 L。任何长度不超过 L 的 XY 曲线，其每个点 P 都必须满足：

```text
distance(A, P) + distance(P, B) <= L
```

对每块多边形的 XY 包围盒 Q，使用更宽松的下界：

```text
distance(A, Q) + distance(B, Q) <= L + 0.05 码
```

只有明显不满足这个必要条件的多边形被排除。它保留符合长度要求的路径可能经过的多边形超集，不是精确最短路证明。

**搜索范围限制不等于结果长度保证。** 合成测试中 L=21 仍能返回长约 24.14 码的绕行，所以输出后的长度、道路偏离和折返检查全部保留。

新增返回码 `10` 只表示：有范围的搜索已结束，但没有得到到达目标的完整 corridor。原返回码 `5` 仍保留给一般查询、最终路径或几何验证失败，不能一概当成图断连。返回码 `6` 继续表示资源限制，并保留具体原因；取消仍为 `7`。

### 2. `adrive/navmesh.py`

- `Mesh.path(..., max_length_xy=None)` 选择旧接口或新接口。
- 新接口返回 `10` 时产生 `road_scope_unconnected`，并记录加载图、长度范围和展开次数，不声称全地图不可达。
- 预算错误保留原生原因；局部错误详情写入道路轨迹。
- 道路余下部分的搜索使用既有 `2.5 × 参考长度 + 20` 上限。
- 保留原半径 1、2、4 的后续加载尝试。在最终范围仍无法连接时，返回 `road_connection_unverified`。
- 没有道路参考的普通自由寻路继续使用原接口。

### 3. `adrive/road_corridor.py`

- 每个参考路段使用原来输出验收的 `2.5 × 参考长度 + 20`，提前限制搜索区域。
- 重新连接历史路径时，使用原来要求的 `旧路径长度 - 0.5`。
- 原有缓存、回退、预算累计、长度检查、道路距离和折返检查保持；新失败类别明确区分完整的范围检查与资源耗尽。

本次没有增加自动道路重选，也没有修改瓦片生成器。它为这两项后续改动提供更准确、成本更低的失败信息。

## 安装、版本与恢复

- 新 DLL 写入不可变目录 `data/navigation/route-search-bounds/<run_id>/adrive_navmesh.dll`，随后只更新清单中的 library 条目。
- 瓦片内容、tile 列表和导航身份保持不变，既有禁行记录仍按原身份与地图规则使用。
- 原 Python 模块、bridge、清单与清单实际指向的 DLL 都有精确备份。
- 多文件写入不假装是单个原子事务；每次写入前比较预期字节，异常时只撤回仍属于本次安装的内容，避免覆盖用户后来修改。
- 不通过降低代理半径、允许高台跨越、放行水标签或拼接直线来使回归通过。

`changes.patch` 用于审阅改动。建议使用带验证的安装器完成应用，不直接手工覆盖生产文件。
